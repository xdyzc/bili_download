# Local Streaming Companion (optional)

`bili_stream_companion.py` is an optional Chrome/Edge Native Messaging host for
large DASH downloads and longer live recordings. It is deliberately separate
from the browser extension and is not enabled merely by placing this directory
in the repository.

The browser extension must continue to obtain every media URL through the
normal, currently authorized page/API flow. The companion never logs in,
reads a browser profile, imports a Cookie file, calls site APIs, or
tries to bypass quality, membership, region, DRM, or copyright restrictions.

## What it does

- DASH: streams the already-authorized video and audio CDN objects to `.part`
  files on disk, switches between supplied CDN candidates, resumes a finite
  download with `Range` when possible, and uses local FFmpeg with `-c copy` to
  create the final MP4.
- Live FLV: writes independently reopened `.flv` segments instead of retaining
  an ever-growing browser `Blob`; retries supplied candidates with bounded
  backoff; produces a local manifest for the segment set.
- Signed URL expiry: when every supplied candidate returns HTTP 403, 404, or
  412, it emits `refresh_required`. The extension can run its normal existing
  prepare operation again and send fresh candidates using the same `taskId`.

The companion has a per-task raw-input disk budget (default 128 GiB) and a
finite live recording duration (default two hours; maximum 24 hours). Before a
task is accepted, the host checks the target volume and reserves a conservative
peak: known DASH sizes reserve both raw inputs and an output-sized mux copy;
unknown DASH sizes reserve the configured raw cap plus the same mux allowance;
live recording reserves its configured byte cap. Active-task reservations are
combined, and DASH space is checked again immediately before FFmpeg runs. A
physical-space admission failure uses the safe `disk_space` error code.

Canceled or failed tasks remove their `.part` and mux temporary files. A DASH
output is committed atomically only after FFmpeg succeeds, so an interrupted
merge does not leave a partial final MP4.

The first live implementation intentionally does **not** byte-concatenate
segments: every reconnect can have a new FLV header and timestamp boundary.
Keeping independent files plus a manifest is safer than silently creating a
corrupt monolithic FLV. A later post-processing flow can remux the completed
segment set explicitly.

## Privacy and access-control boundary

This is a strict boundary, not a convenience workaround.

- It accepts only HTTPS media URLs paired with the matching page origin:
  Bilibili uses `bilivideo.com`, `bilivideo.cn`, `hdslb.com`, and
  `edge.mountaintoys.cn`; Douyu uses `douyucdn.cn`; Huya uses `flv.huya.com`
  and the verified redirect family `mobgslb.tbcache.com`. Every redirect is
  checked against the same site-specific pairing.
- It rejects cross-site CDN combinations, site API URLs, non-HTTPS URLs, credentials embedded in a URL,
  `Cookie`, `Authorization`, `headers`, proxy settings, user-agent overrides,
  browser-profile paths, and Cookie-file fields.
- The only request headers it constructs are a fixed user agent plus safe
  `Accept`, `Origin`, `Referer`, and (for finite DASH resume) `Range` headers.
  The provided referer is canonicalized to one of the supported public page
  origins and determines the fixed `Origin`; arbitrary headers are never accepted.
- Signed URL strings, query strings, and raw network exception text remain only
  in the running process. They are omitted from native events, manifests,
  errors, and terminal output. A completed/canceled task clears its in-memory
  source list.
- Manifests deliberately contain only safe local filenames, byte counts,
  timestamps, and status values. They never include stream URLs, cookies, or
  authorization values.

Because a signed URL is intentionally not persistent, a stopped companion task
cannot silently resume after the host process exits. Start a fresh task through
the extension so it can authorize a fresh source normally.

## Native message protocol

The host name is:

```text
com.bili_download.stream_companion
```

Chrome Native Messaging uses a 4-byte little-endian JSON frame. One JSON event
below is written as one native message; stdout is never used for logs. All
requests have this envelope:

```json
{
  "version": 1,
  "type": "...",
  "requestId": "short_request_identifier",
  "taskId": "short_task_identifier",
  "payload": {}
}
```

`taskId` is generated by the extension and reused for cancellation and source
refresh. Identifiers may contain only ASCII letters, digits, `_`, and `-`.

### Requests

Ping:

```json
{"version":1,"type":"ping","requestId":"ping_1"}
```

Start a finite DASH task. `maxBytes` is the total raw video-plus-audio input
budget; `expectedBytes` is optional but lets the host detect incomplete CDN
responses more reliably.

```json
{
  "version": 1,
  "type": "start_dash",
  "requestId": "req_dash_1",
  "taskId": "task_dash_1",
  "payload": {
    "outputName": "Video title_80.mp4",
    "referer": "https://www.bilibili.com/",
    "maxBytes": 42949672960,
    "video": {"sources": ["<runtime signed CDN URL>"], "expectedBytes": 123},
    "audio": {"sources": ["<runtime signed CDN URL>"], "expectedBytes": 45}
  }
}
```

Refresh an expired DASH task while it is still running. This supplies fresh URLs
only in memory; it does not recreate or persist a task record.

```json
{
  "version": 1,
  "type": "refresh_dash_sources",
  "requestId": "req_dash_refresh_1",
  "taskId": "task_dash_1",
  "payload": {
    "referer": "https://www.bilibili.com/",
    "video": {"sources": ["<fresh runtime signed CDN URL>"]},
    "audio": {"sources": ["<fresh runtime signed CDN URL>"]}
  }
}
```

Start a live recording. `outputName` is a basename, not a path. Segment files
are named `<outputName>.segment-0001.flv`, and the manifest is
`<outputName>.live.manifest.json` inside the host output directory.
The `referer` must match the source family: `https://live.bilibili.com/`,
`https://www.douyu.com/`, or `https://www.huya.com/`.

```json
{
  "version": 1,
  "type": "start_live",
  "requestId": "req_live_1",
  "taskId": "task_live_1",
  "payload": {
    "outputName": "Live title_20260809",
    "referer": "https://live.bilibili.com/",
    "sources": ["<runtime signed FLV CDN URL>"],
    "maxBytes": 42949672960,
    "maxDurationSeconds": 7200,
    "segmentDurationSeconds": 300
  }
}
```

Refresh a live source after `refresh_required`:

```json
{
  "version": 1,
  "type": "refresh_live_sources",
  "requestId": "req_live_refresh_1",
  "taskId": "task_live_1",
  "payload": {
    "referer": "https://live.bilibili.com/",
    "sources": ["<fresh runtime signed FLV CDN URL>"]
  }
}
```

Cancel either kind of running task:

```json
{"version":1,"type":"cancel","requestId":"req_cancel_1","taskId":"task_live_1"}
```

### Events

Every event contains `version: 1`. The host emits:

- `pong` — includes `requestId`, `nativeHost`, and `protocolVersion`.
- `accepted` — includes `requestId`, `taskId`, `kind`, and safe `outputName`.
- `progress` — includes `taskId`, `kind`, `phase`, `receivedBytes`, and, where
  known, `totalBytes`, `segmentIndex`, `durationMs`, or `reconnectAttempt`.
- `refresh_required` — includes `taskId`, `kind`, and `reason: "source_expired"`.
- `sources_refreshed` — acknowledges a refresh request without echoing sources.
- `cancel_requested`, then a terminal `completed`, `canceled`, or `failed`.

Terminal events contain only `taskId`, `kind`, safe `outputName`, byte counters,
the manifest **filename** (not an absolute path), and an allowlisted failure
code/message if applicable. They never echo a source URL.

## Build and register on Windows

The registered native host should be a dedicated executable, not an untrusted
shell wrapper. Build it from this checked-out source first:

```powershell
py -3 -m pip install --upgrade pyinstaller imageio-ffmpeg
py -3 -m PyInstaller --onefile --name bili-stream-companion `
  --collect-all imageio_ffmpeg --hidden-import imageio_ffmpeg `
  .\extension\companion\bili_stream_companion.py
```

Keep `dist\bili-stream-companion.exe` in a location you control. Then find the
unpacked extension ID in `chrome://extensions` (or `edge://extensions`) with
Developer mode enabled, and register only that ID:

```powershell
powershell -NoProfile -File .\extension\companion\install_windows.ps1 `
  -ExtensionId aaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaa `
  -HostExe (Resolve-Path .\dist\bili-stream-companion.exe) `
  -Browser Chrome
```

For both browsers, use `-Browser Chrome,Edge`. The installer writes a native
host manifest under the current user's local application data directory and a
single current-user registry entry. It does not need administrator rights, does
not export credentials, and does not modify the extension itself. Re-run it if
you move or rebuild the executable.

The default output folder is `%USERPROFILE%\Videos\BiliDownload`. For local
development only, the host also accepts `--output-dir` and `--max-disk-gib`;
Chrome starts a registered executable without arbitrary command-line options,
so production configuration should use the default or a controlled launcher
created by a future packaging step.

Chromium may append its invoking `chrome-extension://…/` origin and a
`--parent-window=…` handle to the native host process. The companion recognizes
only those launch-only arguments and ignores them; they are not treated as
media sources or configuration.

## Tests

The tests use fake CDN responses and contain deliberately fake signed query
values. They assert those values do not appear in any emitted event or manifest.

```powershell
py -3 -m pytest .\extension\companion\tests -q
```

They are also compatible with the Python standard library test runner when
pytest is not installed:

```powershell
py -3 -m unittest discover -s .\extension\companion\tests -v
```

## Extension integration

The MV3 extension integrates this host through `chrome.runtime.connectNative`
only after the user explicitly enables the local streaming route in the side
panel. The service worker, not the side panel, owns the runtime Native Messaging
port so an open task remains observable when the side panel is closed. All active
downloads share that port and one host process, allowing disk and output-path
reservations to be enforced across concurrent tasks. The port is disconnected
only after its final task reaches a terminal state.

Only the in-memory start/refresh messages contain signed CDN candidates. The
extension persists a task's safe page identifiers, basename, progress, and
state, never its sources, query strings, headers, cookies, or local paths. On
source expiry it runs its normal currently-authorized prepare flow and sends
fresh candidates using the same task ID. On a lost native port, the task becomes
an explicitly recoverable interruption; **Reauthorize and start** obtains fresh
authorization instead of silently replaying a saved URL.

The browser DASH/live fallback and its memory limits remain available whenever
the companion is not installed or is not explicitly selected.
